# HANDOFF: Claude 5 caregiver-web (partial)
**Built:** see CHECKLIST.md. Login, patient list, trend chart, photo upload, reminder creation, MSW mocks, Playwright test.
**Run:** `pnpm i && pnpm dev` (port 5174). Mocks on when VITE_API_BASE_URL is empty; run `npx msw init public/` once. E2E: `pnpm test:e2e`.
**Endpoints used:** POST /auth/token, GET /sync/pull, POST /sync/push. Entities via sync: PatientProfile, GameSession, Alert, Reminder, MediaAsset.
**CONTRACT CHANGE REQUESTS:** (1) /auth/token response must include role and user_id. (2) Sync payload shapes for Alert (acknowledged, note), PatientProfile (name, band), GameSession (date, score) are my assumptions. (3) Media binary upload route is undefined; only metadata is pushed now.
(4) Co-op room is generated client-side only (no room-create endpoint in contract); SeverityIndicator and MemoryTrigger arrive via sync pull in my assumed shapes.
(5) ConsentRecord and Routine sync payloads are assumed shapes; audio bytes not uploaded (metadata only).
**Known gaps:** PDF export uses browser print. everything under Remaining in CHECKLIST.md. Photo bytes are not uploaded or encrypted. Tailwind configured but UI still uses inline CSS/classes in index.html. Assamese covers core keys only; the rest falls back to English and Assamese strings are unverified by a native speaker. Adapters (src/adapters) are used by Content for mic and file download; api.ts takes an injected Store (setStorage), wired to the web adapter in main.tsx. All Assamese strings need native-speaker review. msw worker is generated by postinstall. Charts use plotly basic bundle (scatter/bar only).
